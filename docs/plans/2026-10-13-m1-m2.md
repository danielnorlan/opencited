## Goal

When this plan is done:

1. The SSB client and the MCP server meet every acceptance criterion of
   [spec 0001](../specs/0001-ssb-mcp-server.md) apart from the hand test with two MCP
   clients and the publication itself.
2. The first release is ready to run: a release workflow with trusted publishing,
   tested up to the upload, and a `server.json` for the MCP Registry. Publishing is a
   separate, manual step.
3. Snapshots, the calculation engine, the evidence gate, the agent and the evaluation
   suite meet specs [0002](../specs/0002-snapshots-and-calculation.md),
   [0003](../specs/0003-evidence-gate.md), [0004](../specs/0004-agent.md) and
   [0005](../specs/0005-evaluation-suite.md), and the first evaluation run is
   published.

## What the research changed

The facts below were checked against primary sources, the live API and test runs on
2026-10-13. They change spec 0001 and add six decision records.

| Finding | Consequence |
| --- | --- |
| PxWebApi 2 is SSB's production API, and the page that spec 0001 cites no longer exists | [ADR 0007](../adr/0007-ssb-pxwebapi-v2.md), and a correction to spec 0001 |
| GET URLs are limited to about 2,100 characters, and a longer URL returns an HTML page | The client switches to POST above 1,800 characters |
| `/config` publishes no call limit; the guide says 30 per minute | The client sends at most 30 requests per minute and backs off on HTTP 429 |
| Figures that are revised at 08:00 are shown as 0 or as a dot from 05:00 to 08:00 | The server returns no data from 05:00 to 08:15 Norwegian time (ADR 0007) |
| SSB's API guide states that the API uses CC BY 4.0 | Open question 4 of spec 0001 is answered in SSB's API guide, and SSB is credited in `NOTICE` and the README |
| The metadata and data responses checked name the responsible statistician, with a phone number and an email address | The fixture recorder removes these contact details before it writes a file ([ADR 0008](../adr/0008-http-client.md)) |
| The MCP SDK 2.3.0 depends on `httpx2`, which no mocking library supports yet | [ADR 0008](../adr/0008-http-client.md): one HTTP stack and a replay transport of our own |
| Pydantic loses digits when it parses JSON numbers as decimals | [ADR 0009](../adr/0009-exact-decimals.md) |
| The MCP adapter for LangGraph requires `mcp` below 2.0, and the `openai` SDK uses the same `httpx2` as the MCP SDK | [ADR 0010](../adr/0010-agent-loop.md): an agent loop of our own |
| DuckDB returns floating point for division and means, allows sums beyond 38 digits, and lets one process at a time open a database file for writing | [ADR 0011](../adr/0011-snapshots-and-exact-arithmetic.md): Parquet snapshots and exact rational arithmetic |
| Inspect AI runs an agent written against the `openai` SDK through its agent bridge | [ADR 0012](../adr/0012-inspect-evaluations.md): Inspect AI for the evaluation suite |
| Babel misreads or rejects common Norwegian number formats | Spec 0003: a tokenizer of our own |
| At DeepSeek's prices of 2026-10-13, 100 questions at 10,000 input and 1,000 output tokens each cost $0.21 to $0.42 on `deepseek-flash` without cache hits | Forty questions stay under $5 on that model at its peak output price, even at the agent's limit of 100,000 tokens per question |

## Work order

Each step is one or two pull requests. The task numbers of each specification are in
brackets.

| Step | Work | Done when |
| --- | --- | --- |
| 1 | Spike [0001: 1]: the fixture recorder and fixtures from tables 06856, 06743 and 05810 | Fixtures are recorded with their dates, and ADR 0007 is accepted |
| 2 | API client [0001: 2]: typed models for search, metadata and data with values parsed as decimals, the replay transport and contract tests | Every client method passes against the fixtures, and ADR 0008 is accepted |
| 3 | Values and provenance [0001: 3]: symbols and their notes, the provenance record, property tests of the parsing and the test that rejects any `float` | The hash in every record matches the raw response, and ADR 0009 is accepted |
| 4 | MCP server [0001: 4]: the three tools, validation, the cell limit, errors, both transports and the end-to-end tests | Every tool works over stdio and over HTTP |
| 5 | Cache and rate limiter [0001: 5], and the nightly live smoke test [0001: 7] | A cached result repeats the original provenance, and the nightly run passes |
| 6 | Packaging [0001: 6]: `opencited mcp`, a release workflow `release.yml` that runs `uv publish` when a GitHub release is published, `server.json` and client setup in the README | `uvx opencited mcp` starts from the built package in CI, and a manual run of the release workflow builds and checks the files without uploading them |
| 7 | Snapshots [0002: 1] | Snapshots of the fixtures match the raw responses cell for cell, and ADR 0011 is accepted |
| 8 | Calculation engine [0002: 2 to 4] | Every operation matches exact rational arithmetic in property-based tests |
| 9 | Evidence gate [0003: 1 to 4] | Every rule has tests in both languages, and the example corpus passes |
| 10 | Agent [0004: 1 to 4] | The decision functions, the limits and the assembly of answers are tested |
| 11 | Evaluation suite and the first question set [0005: 1 to 3], with fixtures for every table that the reference plans read | Every reference plan runs against fixtures in CI |
| 12 | First published run [0005: 4] | A complete run with a pinned hosted model is committed under `evals/results/`, and ADRs 0010 and 0012 are accepted |

Each decision record is accepted in the pull request of the step that names it.

## Open decisions

1. Before the first release, register a pending publisher on PyPI for `release.yml`
   in this repository, and publish once the repository is public. A listing in the
   MCP Registry needs a login with the registry's publishing tool.
2. Before step 12, and if possible before step 10, choose the model, the budget of
   the run, the temperature and seed, and whether the provider may keep prompts, and
   provide the API key.
3. Optionally, ask SSB in writing about the rate limit, since the guide says 30
   requests a minute and the responses state 40 per 60 seconds, and about the
   licence of data from the API.

## Risks

| Risk | Response |
| --- | --- |
| The MCP SDK 2.x is three months old and releases often | Pin the minor version and upgrade through Dependabot |
| SSB runs PxWebApi 2.5.0 while 2.7.0 exists, so behaviour can change | Tolerate unknown fields, log the versions from `/config`, run the nightly smoke test |
| No recorded response with the symbols `.` or `:` exists yet | Unit tests cover the symbol table, and contract tests for these symbols follow when a recording contains them |
| The server returns no data from 05:00 to 08:15 every day | Scheduled jobs and evaluation runs avoid that period, and the error names the reason |
| Tool calling differs between models and endpoints | The published run records the endpoint and the model, and the agent only runs tool calls that match a schema |
| The gate refuses correct answers | The evaluation suite counts these refusals, and the rules change only through spec 0003 |
| Inspect AI releases every few days | Pin it exactly in the `evals` group and update it on purpose |

## Out of scope

- Table search with embeddings, the model gateway and tracing (M3).
- The demo site, the results page (M4) and other sources.
- Running a model in CI.
